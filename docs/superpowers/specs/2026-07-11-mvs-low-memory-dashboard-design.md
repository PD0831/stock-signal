# MVS 低内存决策台与 15 分钟宽度设计

## 目标

在 Render 免费版 512MB 内存限制下，将 Market Vital Signs 网页改造成稳定的每日决策台，并新增独立的 15 分钟市场宽度盘中雷达。网页必须优先回答“现在做什么、买什么”，同时避免服务器实时处理 500–600 只股票造成内存溢出。

## 已确认的产品方向

- 主页用途优先级：每日快速判断市场状态并查看买入或做空标的。
- 市场宽度：独立 15 分钟页面，主要在美股交易时段使用。
- 主页风格：行动优先。
- 买入标的排版：C 专业表格。
- 15 分钟宽度排版：A 盘中雷达。
- 运行约束：继续使用 Render 免费版，不通过升级内存解决问题。

## 当前内存问题

当前 Render 进程启动时会在后台计算市场宽度：下载约 500 只股票的两年日线和三个月小时线，拼接成宽 DataFrame，再计算 MA20、MA50、MA200 及派生指标。同时，信号接口还会下载并缓存 NASDAQ-100 与 S&P 500 的 18 个月 Close/Volume 历史。

批量下载、`float32` 和 LRU 缓存能够降低部分峰值，但无法改变以下结构性问题：

1. 所有批次最终仍被拼接为全市场宽表。
2. 日线、小时线、移动均线、比较矩阵和最终结果会在计算期间同时存在。
3. 信号历史和 breadth 结果会进入同一进程的内存缓存。
4. 后台线程与用户请求可能同时触发行情工作负载。

因此，512MB 下的可靠方案不是继续微调批次，而是把全市场计算移出 Render 请求进程。

## 总体架构

### 计算层：GitHub Actions

GitHub Actions 负责所有高内存和外部行情工作：

1. 获取 NASDAQ-100、S&P 500 或 SPY holdings 成分股。
2. 下载用于选股的日线 Close/Volume。
3. 计算 ADV 排名、MA200 距离、60/20/20 买入权重及弱股雷达。
4. 在美股交易时段下载 15 分钟或可用的最接近粒度行情，计算 Strong、Breakdown、NTSS、Momentum、阶段与状态切换。
5. 将网页实际需要的数据写成小型版本化 JSON。

工作流在美股交易时段按 15 分钟计划运行；实际执行时间允许受 GitHub Actions 调度延迟影响。非交易时段保留最后一次收盘结果，不反复下载相同数据。

### 展示层：Render

Render 只承担：

- 提供 FastAPI HTML 页面和轻量 JSON API。
- 从仓库内预计算文件或 GitHub Raw 地址读取小型 JSON。
- 对 JSON 做基本格式验证和新鲜度判断。
- 渲染主页与 15 分钟宽度页。

Render 进程不得在启动、页面请求或 API 请求中调用 `yfinance`，也不再启动 breadth 后台线程。常驻缓存仅允许保存小型反序列化结果，不保存全市场 DataFrame。

## 数据产物

预计算层至少生成两个独立文件：

### `data/dashboard_snapshot.json`

包含：

- schema 版本、生成时间、行情日期和数据新鲜度。
- 当前市场阶段、行动标签、行动说明和 Risk Off/Trail 状态。
- NASDAQ-100 与 S&P 500 的有效股票数、失败数和数据来源。
- 合并买入表格所需的 symbol、universe、rank、distance_pct、target_weight_pct、close、adv_rank。
- 做空代理、弱股候选和执行限制。

### `data/breadth_15m.json`

包含：

- schema 版本、生成时间、交易时区和数据质量信息。
- 当日或有限回看窗口内的 15 分钟 records。
- 每条记录的 Strong、Breakdown、NTSS、Momentum、阶段代码和行动状态。
- 最近一次状态切换的时间、旧状态和新状态。
- 可展开研究区所需的 MA20、MA50、MA200 宽度及有效成分股数。

网页不得依赖完整股票历史，只消费这些已聚合字段。

## 主页设计

### 信息层级

1. 顶部状态卡：当前行动、多头/空头/等待、市场阶段、更新时间和数据新鲜度。
2. 四项关键依据：Strong、Breakdown、NTSS、Momentum 或最相关的四项状态指标。
3. 买入标的专业表格。
4. 空头雷达与风险限制。
5. 数据质量和方法说明折叠区。

### 买入标的专业表格

NASDAQ-100 与 S&P 500 候选合并为一张表，默认按执行优先级展示。列为：

- 排名
- 股票代码
- 市场
- MA200 距离
- 目标权重
- 最新价格
- ADV 排名
- 数据时间

桌面端完整展示。移动端固定排名、代码和目标权重，其余次要列允许横向滚动或折叠。视觉上突出第一执行标的和最高目标权重，但不使用装饰性图形削弱数据密度。

## 15 分钟宽度页设计

采用盘中雷达布局：

1. 顶部显示当前阶段、当前行动和最近更新时间。
2. Strong、Breakdown、NTSS 三个核心指标显示当前值与相对上一根 15 分钟记录的变化。
3. 主图展示当日 Strong 与 Breakdown 轨迹，并清楚标出状态切换点。
4. 状态变化提示显示最近一次阶段转换，例如“B 强势整固 → E 震荡整理”。
5. MA20、MA50、MA200 宽度、Momentum、有效成分股数和数据口径放入可展开研究区。

页面以快速判断为主，不把所有研究指标同时放在首屏。

## 错误与降级策略

- Action 计算失败：不覆盖最后一次成功产物，并记录失败工作流状态。
- JSON 缺失或 schema 不兼容：API 返回明确的 unavailable 状态，页面显示“数据暂不可用”，不显示伪造的零值。
- 数据过期：继续显示最后一次成功数据，同时以醒目但非阻塞方式标记“数据已过期”和最后更新时间。
- 个别股票失败：保留有效候选，展示有效数与失败数；候选不足时明确提示，不能静默改变策略规则。
- 15 分钟数据在非交易时段不视为故障，页面显示“市场已收盘”和最后收盘记录。
- Render 不因外部行情源不可用而崩溃，因为展示请求不直接访问行情源。

## 测试与验收

### 计算层

- 固定行情样本验证选股输出、权重、breadth 指标和阶段切换。
- 验证两个 JSON 产物符合 schema，时间字段带时区，缺失值可序列化。
- 验证失败运行不会覆盖最后一次成功产物。
- 修复远端已有的 available-history MA 和 `daily_close_payload(..., denominator=...)` 两个 breadth 回归测试。

### 展示层

- 验证加载正常、过期、缺失和 schema 不兼容 JSON 的 API 响应。
- 验证主页专业表格的列、排序、权重和移动端关键字段。
- 验证 15 分钟页的当前值、变化量和最近状态切换。
- 通过测试替换或禁止 `yfinance`，证明 Render 的启动和全部展示路由不会触发行情下载。

### 资源验收

- 在接近 Render 启动方式的单 worker 环境中测量常驻内存。
- 依次请求主页、dashboard API、15 分钟页和 breadth API，确认 RSS 不随请求显著累积。
- 验收目标：不再创建全市场 DataFrame；稳定状态内存明显低于 512MB，并保留足够余量应对部署与请求波动。

## 发布流程

1. 在包含远端最新 `main` 和 NASDAQ URL 修复的集成分支实施。
2. 运行计算层、展示层、回归测试和内存基准。
3. 在合并后的 `main` 再次验证。
4. 推送远端 `main`，由部署流程发布。

## 非目标

- 不在本次工作中更改 MVS 的交易信号定义或选股研究结论。
- 不通过升级 Render 付费实例规避内存问题。
- 不在 Render 内保留实时全市场计算作为备用路径。
- 不把主页改造成面向普通用户的通用股票筛选器。
